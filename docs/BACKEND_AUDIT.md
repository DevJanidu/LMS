# Backend integration audit

Source of truth: [SRS.md](SRS.md), copied unchanged from the repository's final SRS. The owner chose Argon2 hashing and the SRS's 0% / “No topics yet” behavior.

The former implementation generated a workspace in `lib/mock/seed.ts`, authenticated by navigating to another page, and persisted every mutation in localStorage. No database, authentication library, email transport or file storage existed.

| Former entry point | Replacement |
| --- | --- |
| `getWorkspace()` | Authenticated server loader in `lib/services/workspace.ts` |
| `getSubjects`, `getTopics`, `getSessions`, `getTodaySessions`, `getResources` | Pure selectors over server-projected records in `lib/workspace/queries.ts` |
| `getLearnerStatistics` | Projection over an admin-authorized workspace; private text is omitted by the SQL selection |
| `useWorkspace`, `updateWorkspace` | Memory-only optimistic UI plus validated Server Actions; database transactions are authoritative |
| `newId`, `useNow` | Browser UUID generation and a presentation clock; neither controls ownership or timer duration |
| `getOccurrences` | Shared, tested recurrence expansion, also used by authenticated server range queries |
| `getNotifications` | Reads persisted notifications generated by secured cron jobs |
| Auth form navigation | Better Auth sign-up, sign-in, logout and password-reset actions |
| File metadata form | Private presigned upload, HEAD verification, reserved quota and immutable final key |
| Timer callbacks | Explicit server commands with server timestamps and one database timer per learner |

`lib/mock` was removed. The production seeder creates an account and settings only; no fabricated learning activity is inserted. The existing UI is retained, including translations, dark mode, RTL, empty states and loading/error boundaries.

Data flow:

```text
Localized Server Component -> session + role guard -> Drizzle services -> Neon
Client form -> Zod operation -> Server Action -> user row lock + scoped transaction
File -> short-lived PUT -> private temporary object -> HEAD -> immutable object -> resource
Cron bearer secret -> idempotent reminders / timer cap / deletion retries / retention
```

Current limits requiring production measurement: the compatibility workspace loader still materializes bounded batches of subjects, topics, resources and admin activity. Session history itself is paginated on the server, learner daily analytics are aggregated in SQL, and recurrence range queries run on the server. Do not treat dashboard latency or scale targets as verified until measuring against the specified large fixtures on an isolated Neon branch.
