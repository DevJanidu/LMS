# Aven gap analysis

Specification: `docs/aven.md`. Baseline: commit `dbe34c2`. Findings below distinguish static defects from unsupported product capabilities. Earlier screenshots predate several shipped fixes; they are not proof that every original fault still exists. New runtime verification is recorded in the implementation report.

## Existing working foundation

The app already uses the real OpenAI Responses API with streaming and account-scoped function calling. Eighteen tools read persisted LMS state or create approval proposals; writes run in authenticated transactions. Goals, calendar edits, reminders, resource processing, user memory, private conversation history, timezone detection, delivery leases, deduplication, and a shared $5 monthly application allocation are implemented. The external cron endpoint works independently of OpenAI. AI consent and browser notification permission are separate. No production mock AI implementation was found.

## Implementation policy

Read operations remain automatic. Opted-in routine check-ins remain deterministic and free of OpenAI generation costs. State changes remain explicit, scoped approval proposals; destructive actions require confirmation. Existing simple goal forms, UTC storage, device/manual timezone choices, learner privacy, and the shared monthly app cap are preserved. Do not introduce a new scheduler vendor or package solely to replace the functioning external cron worker.

Official API references: [function calling](https://developers.openai.com/api/docs/guides/function-calling), [streaming](https://developers.openai.com/api/docs/guides/streaming-responses).

## Additional findings during implementation and live verification

- **A32 High, budget integrity:** deleting an account cascaded its usage records out of the shared monthly ledger. Migration `0009_aven_usage_retention.sql` now anonymizes the owner while retaining token/cost metadata. A real database test verifies retention. No chat text, email, or account identity is retained in these usage rows.
- **A33 High, tool integration:** a single-day calendar query could pass equal dates to an exclusive range, producing a tool error and a misleading unavailable-schedule reply. The tool now documents its range contract and normalizes equal dates to one local day. The real provider journey retrieved both saved sessions after this fix.
- **A34 High, reply accuracy:** a model occasionally described an unapproved goal proposal as already created. Pending-change text is buffered, changing tools explicitly return `changeApplied: false`, and common unsupported execution claims trigger a real corrective provider request within the same usage bound. The UI also prevents approval during generation. The guard supplements transactional approval; it is not a general semantic verifier of arbitrary model prose.
- **A35 Medium, notification navigation:** changing between notifications in a grouped thread could leave old messages loaded, and selecting another conversation could retain an unrelated reminder context. A committed reply now forces history reload; history navigation clears reminder context and updates the owned conversation URL.

- **A36 High, cross-day scheduling:** a write tool's `date` could be interpreted as the destination rather than the original occurrence. The schema now describes source versus destination explicitly, and one-time blocks resolve their unique source occurrence from the owned saved ID. A genuine missed-session reply successfully moved the session to the next day after approval. Recurring occurrences still require their original identity.

All findings above are linked to implementation and verification in `AVEN_IMPLEMENTATION_REPORT.md`. Tests involving a real external database have bounded but larger allowances than unit tests; the long task/dependency regression took 141 seconds across many network transactions, not one UI operation.
